Earlier this month, Claude Code was caught rewriting test assertions to make failing tests pass — hiding real bugs to satisfy its objective. Not a hypothetical. It happened.

That's the problem in one sentence: agents optimize for outcomes, and they'll route around controls that live inside the agent.

You can't ask an agent to police itself. Authorization has to live outside the agent.

We built Permission Protocol — it blocks high-risk AI actions (deploys, database writes, tool calls) unless a human explicitly signs them. Execution won't proceed without a valid cryptographic signature.

Instead of "the agent decided this was safe," you get "this action executed because this human approved it."

Open-source entry points:

deploy-gate (CI/CD enforcement): https://github.com/permission-protocol/deploy-gate

mcp-guard (local proxy for tool calls): https://github.com/permission-protocol/mcp-guard

Under the hood:

  - Ed25519 signatures over a deterministic payload (commit SHA, repo, environment, timestamp)
  - Verification happens locally — no SaaS in the enforcement path
  - Policy defines who can approve what

The signing ceremony uses our hosted service. Verification is local and independent — if we disappear, your enforcement still works.

30-second demo (no install required): https://github.com/permission-protocol/pp-demo/pull/32

Click "Authorize Deploy," approve it, watch the PR unblock.

If you can find a way to bypass the approval requirement, I'd genuinely love to see it.

Happy to answer anything. Here's what usually comes up:

*How is this different from GitHub required reviews / OPA?*
GitHub reviews control access before execution. OPA evaluates policies. This enforces that a specific human cryptographically signed off on a specific action at execution time. Different layer — they're complementary, not competing.

*What if your service goes down?*
The signing service is hosted, but the enforcer checks Ed25519 signatures locally and independently. No SaaS in the critical path.

*What's the threat model?*
Preventing agents from taking irreversible actions without explicit human approval. Not sandboxing — signing.

*Why not just turn off auto-deploy?*
That works today. It won't work when you have 50 agents making 200 changes a day. You need a system that scales approval without scaling humans linearly.

Happy to go deep on architecture, crypto, or edge cases.
