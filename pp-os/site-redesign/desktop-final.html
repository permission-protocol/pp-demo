Common questions

How does it differ from traditional RBAC?

expand_more

Traditional RBAC is identity-based at the gateway. Permission Protocol is intent-based at the execution point, requiring a fresh signed receipt for every high-stakes payload.

Does this introduce significant latency?

expand_more

Median latency for a gate check is under 200ms. The approval wait time depends on your signers, but we provide multi-channel routing (Slack/SMS) to minimize delays.

Is the enforcement layer open source?

expand_more

Yes, the enforcement SDKs and local verification libraries are MIT-licensed. You own the code that says 'Yes' or 'No'.

Can an agent bypass the protocol?

expand_more

Not if you place the gate at the resource level (e.g., inside your deployment runner or database proxy). The resource won't accept commands without a valid signed receipt.

What counts as a protected repo?

expand_more

Any repo where you install the Deploy Gate. Unprotected repos are unlimited on all plans.

What if I hit my repo limit?

expand_more

You'll be prompted to upgrade. Existing protections stay active — we never silently disable enforcement.
