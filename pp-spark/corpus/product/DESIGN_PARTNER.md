# Permission Protocol Design Partner Program

## What This Is

The Design Partner Program is how we build Permission Protocol v1.0 with real practitioners, not in isolation.

Design partners are **co-authors of the standard**, not beta users.

## Who Should Apply

You should apply if your organization meets **at least one** of these criteria:

| Criteria | Why It Matters |
|----------|----------------|
| Agents can touch production | You need real authorization boundaries |
| Agents can touch money | Financial actions require audit trails |
| Agents can message users | Customer communication needs approval gates |
| CI/CD already exists | You have infrastructure to integrate receipts |

If none of these apply, Permission Protocol may not be the right fit yet.

## What Design Partners Do

Design partners commit to:

1. **Integrate the SDK in a real workflow.** Not a toy project. A real agent doing real work.

2. **Share 1-2 receipt examples.** Blocked actions, approved actions, or approval flows. Anonymized is fine.

3. **Give feedback on:**
   - Receipt schema (are the fields right?)
   - CI gating patterns (does the GitHub Action work?)
   - Approval ergonomics (is the flow usable?)

4. **Participate in async feedback loops.** Slack, email, or GitHub discussions.

This is not a passive beta. You're shaping the standard.

## What Design Partners Get

- **Early access** to SDK releases and spec changes
- **Direct channel** to the core team (Slack or email)
- **Input on v1.0** before it freezes
- **Attribution** in launch materials (optional)

We do not offer:
- Free hosting forever
- Custom features
- Enterprise support contracts

## What We're Looking For

We want 5-10 design partners who:

- Have agents in production (or nearly there)
- Care about authorization and audit trails
- Will give honest, critical feedback
- Understand this is pre-v1 software

We are not looking for:
- Tire-kickers
- "We'll try it someday" commitments
- Feature request factories
