# Learning: Render API PUT vs PATCH
**Date:** 2026-03-09
**Context:** Attempting to update Render environment variables for `pp-web` (Permission Protocol app).
**Error:** Used `PUT /services/{serviceId}/env-vars` which replaces the entire list of environment variables.
**Impact:** 20+ critical environment variables (signing keys, OAuth secrets, encryption keys) were wiped, partially breaking the production app.
**Correction:** 
1. Always use `GET` to fetch current state before a destructive `PUT`.
2. Check if a `PATCH` endpoint exists for partial updates (Render uses `PUT` for the whole array, but some tools/SDKs have helper methods).
3. **MANDATORY:** Back up existing configuration to a local file (e.g., `backups/render-env-vars-YYYY-MM-DD.json`) before ANY write operation to an external infrastructure provider (Render, Vercel, AWS, etc.).
4. Verify the request payload contains the full expected state, not just the changes, if using a replacement-style API.
