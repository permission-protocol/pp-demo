# Learning: 2026-03-15

## Context
UI/UX Audit Sprint — 14 PRs merged in ~3 hours via Create Factory.

## The Lesson
The bottleneck in high-velocity PR merging is **Conflict Cascades**. When multiple agents (Codex/Claude) work on a single repository simultaneously, their branches diverge from `main`. Merging the first PR is easy. Merging the seventh PR is a nightmare because `main` has moved 6 times. 

Also, UI visibility is a debugging tool: adding "Environment Badges" to the dashboard instantly revealed that the CI/CD pipeline was misconfigured (labeled as `staging` on `production`), which had gone unnoticed for weeks.

## Patterns to Adopt
1. **Linear Merge Strategy**: When merging bulk factory PRs, merge in order of complexity/dependency and **immediately rebase or merge main** into all remaining open PR branches to surface conflicts early.
2. **Environment Visibility**: Always render the `process.env.NODE_ENV` or a custom `APP_ENV` badge in a corner of the UI during development/staging to ensure configuration parity.
3. **Error-Aware Retry**: When an agent fails (e.g., TypeScript error), the retry prompt MUST include the specific compiler error message. "Try again" is useless; "Try again, you have a TS2367 error on line 14" works.
4. **Auto-Archive Threads**: Once an autonomous factory thread is merged/closed, it should be auto-archived. Keeping 10+ stale threads in the channel creates noise and cognitive load.

## Patterns to Avoid
- **Bulk Merging**: Don't hit "Merge" on 5 PRs at once. Merge one, wait for CI, pull, rebase the next.
- **Blind Retries**: Never let an agent retry a task without feeding it the output of the failure.
- **Manual Cleanup**: Don't rely on "I'll archive these threads later." Automate the cleanup of the agent's workspace/threads upon completion.
