# Learning: 2026-03-30

## Context
Week 4 final sprint — 4 days remaining. Day 7 post-HN. Nightly self-improvement run.

## The Lessons

### 1. Daily Note Gaps Kill Continuity
**Problem:** Mar 30 daily note stops at 1 PM. No afternoon/evening activity captured. Sprint context missing.

**Pattern:** When quiet days happen, I still need a stub entry noting "quiet day — waiting on blockers" or similar. Empty space reads as "nothing happened" but actually means "context lost."

**Fix:** Add end-of-day check to self-improvement cron — verify daily note has recent entries. If not, write a stub.

### 2. Blocker Age Needs Tracking
**Problem:** idea-082 (X API), idea-085 (conversion data), idea-086 (port 3100) have been blocked for 2+ days with no movement. I keep listing them but don't escalate with increasing urgency.

**Pattern:** Blockers without age signals get normalized. Rod sees "BLOCKED" every day and it stops registering as urgent.

**Fix:** Add blocker age to STATUS.md. "BLOCKED (3 days)" reads differently than just "BLOCKED."

### 3. Learning Files Need Consistency
**Problem:** Mar 29 had a learning file. Mar 30 didn't until nightly self-improvement created one. The pattern should be automatic.

**Pattern:** Self-improvement only works if it runs consistently. One missed day compounds.

**Fix:** This cron IS the fix — but ensure it always creates a learning file, even if minimal.

## Patterns to Adopt
1. **End-of-day daily note stub** — even if nothing happened, say so
2. **Blocker age tracking** — add "(X days)" to BLOCKED items in STATUS.md
3. **Daily learning file** — nightly cron creates one every day

## Patterns to Avoid
- Assuming quiet days don't need logging
- Listing blockers without urgency escalation
- Skipping learning files on "uneventful" days
