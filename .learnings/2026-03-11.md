# Learning: Embedded Worker vs. Infrastructure Complexity
**Date:** 2026-03-11
**Context:** Facing delays in creating a separate Render worker service for Permission Protocol jobs (merges, CI reruns).
**Pattern:**
1. **Prefer Embedded Workers for Low-Medium Scale**: If a task can be handled in-process (e.g., using a background job library with the same DB), don't force a separate service deployment. It reduces DevOps friction for the user ("one service to rule them all").
2. **"The Right Way" First**: Don't settle for quick infra hacks (e.g., manual Render creation) if an architectural improvement (embedded worker) solves the root cause and simplifies the GTM.
3. **Receipt Signing Continuity**: Environment wipes (like Render redeploys) kill local signing keys. Always use persistent secret storage (1Password, GitHub Secrets) for keys used to verify historical receipts to avoid bricking existing PRs on redeploy.
4. **Visual QA Pipeline**: Coding agents (Codex) can't see the UI. Always run `pre-merge-review.sh` to capture screenshots of frontend changes before merging. If they pass, merge; if not, steer.
