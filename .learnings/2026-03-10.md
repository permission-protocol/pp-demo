# Learning: Atomic Approvals and Carry-Forward
**Date:** 2026-03-10
**Context:** Upgrading Permission Protocol's approval flow to handle expired receipts and PR-level approvals.
**Pattern:**
1. **Re-approval Logic**: When a receipt expires or the SHA changes, provide a "Re-approve" path that carries over the previous intent while generating a fresh signature for the new state.
2. **PR-Level Persistence**: Approvals should optionally attach to a Pull Request (via PR number) rather than just a specific Git SHA. This allows minor changes (fixing typos, rebasing) to "carry forward" an approval without requiring a human to re-review every tiny change.
3. **Receipt Expiry**: Always return explicit error codes (`RECEIPT_EXPIRED`) rather than generic 400s to allow the client (Action/CLI) to guide the user toward the re-approval flow.
4. **Post-Approval Reliability**: Long-running actions after an approval (merging, CI reruns) should be backgrounded (queues/jobs) rather than handled in the request-response cycle to avoid timeouts.
