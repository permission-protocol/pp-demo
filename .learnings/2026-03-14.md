# Learning: 2026-03-14

## Context
Debugging GitHub App "No repositories connected" issue on Permission Protocol dashboard.

## The Lesson
Silent failures are the most expensive. The GitHub App installation seemed successful, but the product was non-functional because webhooks were being blocked by the application middleware (401 Unauthorized) and the callback was using the wrong token type (App JWT instead of Installation Token).

## Patterns to Adopt
1. **Middleware Check**: Every new `/api/*` route intended for external webhooks MUST be audited against `middleware.ts`. If it's not in `PUBLIC_PATHS`, it will fail before the route logic even runs.
2. **GitHub Token Specificity**:
    - **App JWT**: Used for "meta" actions (listing installations, getting installation details).
    - **Installation Token**: Used for repo-specific actions (listing repos, commit statuses, PR comments).
3. **Verify Reachability**: Use a tool (like `curl` or a browser) to hit new webhook endpoints from the *outside* (or check logs immediately after installation) to ensure they aren't being intercepted by auth.

## Patterns to Avoid
- Assuming an integration is "working" just because the UI flow completed.
- Delaying the check of "Recent Deliveries" in the GitHub App dashboard when data doesn't appear.
