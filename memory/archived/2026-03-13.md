## Safari WebDriver on iPhone SE — BREAKTHROUGH

### The Problem
iPhone Mirroring (wireless) lets Peekaboo take screenshots but blocks ALL programmatic interaction — mouse clicks, typing, paste. Apple security measure. Keyboard-only navigation was the plan B.

### The Fix: Safari Remote Automation
Rod enabled two settings on iPhone Safari (Settings → Apps → Safari → Advanced):
1. **Web Inspector** — allows external tools to inspect Safari pages
2. **Remote Automation** — allows external scripts to control Safari (security master switch)

### What Worked
- iPhone SE connected via **Lightning-to-USB-C data cable** (charge-only cables don't work — no USB device shows up)
- `pymobiledevice3` confirmed device: serial `00008110-000255A41A78401E`, connection type USB
- `safaridriver -p 4444` (built into macOS) creates WebDriver sessions targeting `platformName: "ios"`
- iPhone shows "Safari is Running an Automated Test" — user must tap **"Continue Testing"**
- Phone must be **unlocked** for session creation (returns "device is locked" otherwise)
- First attempt: pairing failure (Mac Safari needed developer settings). Second attempt: ✅

### Full Capabilities Confirmed
- **Navigate:** `POST /session/{sid}/url` → loads any URL on iPhone Safari
- **Screenshot:** `GET /session/{sid}/screenshot` → base64 PNG (content only, no Safari chrome)
- **Find elements:** CSS selectors work — found 35 links, 11 buttons, nav, H1, H2s
- **Execute JS:** `window.innerWidth` → 375px, `document.body.scrollHeight` → 9811px, `devicePixelRatio` → 2
- **Scroll:** `window.scrollBy()` via JS execution
- **Read text:** Element text extraction works perfectly

### Known Issues
- safaridriver exits between script invocations — all commands must run in one session/script
- Screenshots render as black (dark-themed site + possible timing issue). DOM access works perfectly regardless.
- `safaridriver --enable` needs sudo (one-time, may already be done)
- Safari developer settings can't be set via `defaults write` on Tahoe (sandbox). Must be set manually in Safari → Settings → Advanced → "Show features for web developers"

### Architecture
```
safaridriver (port 4444) ←→ USB cable ←→ iPhone Safari
        ↑
   WebDriver protocol (HTTP JSON)
        ↑
   Python/curl/any HTTP client
```

No Xcode needed. No iPhone Mirroring needed. Direct DOM control.

### Impact
This completely replaces the iPhone Mirroring interaction approach. We now have:
- Click any element by CSS selector (not coordinates)
- Type text into form fields
- Run JavaScript on the page
- Full DOM inspection
- Programmatic navigation
- Scroll to any position
