## Insights
- **Byte-Equivalence vs Semantic JSON**: Signed `requestJson` as a string field requires exact byte-matching. Logical equivalence isn't enough; formatting changes invalidate the signature. This is a deliberate security trade-off for v1.
- **Distribution Signaling**: Implied distribution (like a Marketplace badge) must be real. 404s on badges are instant credibility killers.
- **Onboarding Funnel**: Every extra field in a quickstart is a drop-off point. Defaulting the API URL removed 50% of the required setup secrets.

- **GitHub App token for statuses:** Branch protection's "Required status check was not set by the expected GitHub app" warning blocks merges when statuses are set via PAT. Must use the actual GitHub App installation token (JWT → installation token → POST /statuses) to satisfy branch protection.
- **Enrichment overwrites manual edits:** When pushing a new commit, the webhook re-enriches and overwrites manually-edited bot comments. Don't push empty commits after manually editing — the enrichment will clobber the changes.
- **Demo PR pattern:** For future demo recordings, the script is: create branch → commit realistic code → create PR → wait for webhook to fire → manually edit comment to final copy → set status to pending via App token → record. Don't touch the PR after setting up the state.
