## P0: Permission Protocol CI Auth Fix

Rod requested fix for `/pp <requestId>` returning "Authentication required".

### Root Cause
1. Plugin used Basic auth with CLI_API_KEY format
2. PP now uses modern `X-PP-API-Key` header with `pp_live_xxx` keys
3. GitHub Actions PP_API_KEY was legacy format (hex string)
4. Verify action parsed multiple `errorCode` values incorrectly (newline bug)

### Changes Made

**PR #30** (feat/api-key-auth-deploy-requests):
- Added `api-key-auth.ts` helper for X-PP-API-Key validation
- Updated `withTenant()` to support `enableApiKeyAuth` option
- Added API key auth to deploy-requests GET/approve/deny endpoints
- Added API key auth to approvals endpoints
- Scopes: `deploy-gate:read`, `deploy-gate:write`, `approvals:read`, `approvals:write`

**Verify Action Fixes:**
- Added `commit_sha` input to override `github.sha` for PRs
- Use `pull_request.head.sha` instead of merge commit SHA (scope mismatch fix)
- Pass `pp_request_create_token` for auto-create flow
- Fixed `errorCode` parsing: use `tail -1` to get top-level value
- Enhanced output with request ID, approval URL, Telegram command

**Plugin Updated** (`~/.openclaw/extensions/pp-approval/`):
- Uses `X-PP-API-Key` header
- Hits correct endpoints: `/api/v1/deploy-requests/{id}`
