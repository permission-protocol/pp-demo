## PP User Requirements Deep Dive

Major planning session with Rod in Discord #user-requirements thread.

### Marco Requirements (Final v2)
- Created comprehensive user requirements for Marco ("The Solo Shipper") persona
- 29 requirements across 5 sprints
- Key design decisions:
  - **Delegate merge orchestration to GitHub's native merge queue (v1)** — PP owns governance layer, not merge plumbing
  - **Pre-compute all enrichment at PR creation** — AI summary, risk signals, verification steps, preview URL. Never on page load.
  - **Information hierarchy: WHY → WHAT → HOW IT LOOKS → HOW TO VERIFY → HOW DANGEROUS → CODE → OPTIONS**
  - Marco should never need to read code to make an approval decision
  - AI summary quality is the #1 dealbreaker feature
  - Approval ≠ Merge (separate concepts, separate actions)
- New requirements beyond initial draft:
  - M3a: Visual preview embed (deploy preview from Vercel/Netlify)
  - M3b: AI-generated verification checklist
  - M3c: Origin context (link to issue/factory that spawned the PR)
  - M17: Rejection with structured reproduction context (feedback loop to agents)
  - M19: Approval revocation (undo before merge)
  - M20: Review iteration tracking (PR rejected 3 times = flag)
  - M21: Stale request handling (re-enrich after 48h)
  - M22: Incident tracing + one-click revert
  - M23: Risk-gated approval friction (opt-in)
  - M24: Summary confidence / disagreement detection
- Competitive positioning: PP sits between "agent created PR" and "human says go" — nobody else does this
- Saved to: `pp-os/specs/marco-user-requirements.md`

## Create Factory Upgrades (GSTACK Steal)

Analyzed Garry Tan's `gstack` repo (10 role-based Claude Code skills) and identified high-leverage patterns for our factory.

### Quality Gates Added
Built and deployed 4 new automated quality gates into the factory pipeline:
1. **CEO Review**: Strategic alignment and user value check (Gemini Flash).
2. **Engineering Review**: Implementation architecture and complexity audit.
3. **Paranoid Code Review**: Security, side-effects, and edge-case detection.
4. **Ship Script**: Formalizes the "Done" transition (tagging, merging, archiving WIP threads).

### Improvements
- Added **QA Health Scoring (0-100)** to factory items.
- Structured QA report template with specific pass/fail evidence.
- Versioned review checklists for consistent evaluation.
- Documented future steal plan (browser-based visual QA, bisectable commits) in `factory/GSTACK-STEAL-PLAN.md`.

Cost impact: ~$0.05 added per factory item (Flash). Value impact: Significant reduction in "blind merges" and quality regressions.
