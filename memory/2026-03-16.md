## URL Consolidation — Marketing vs App Surface Audit & Build

### Problem
Two codebases (`permissionprotocol-site` + `permission-protocol-app`) serving overlapping authenticated workflows. Marketing site grew a full review system with its own NextAuth, API proxy layer (7 routes forwarding to app API), and enrichment pipeline (Gemini AI summaries). Bugs reported against one site, fixes built on the other.

### Full Audit
Wrote comprehensive audit at `pp-os/audits/url-surface-audit-2026-03-16.md`:
- 5 overlapping surfaces identified (review dashboard, review detail, receipt, bridge page, 2 demo pages)
- Marketing site runs full proxy backend (own auth, own AI enrichment, own approve/reject/merge APIs)
- GitHub CI status checks pointed to marketing site, not app
- Marketing `/approve/[id]` and `/replay/[id]` are demo-only (hardcoded data, not functional)

### Final Spec
Written at `pp-os/specs/url-consolidation-spec.md`. 4-phase plan:
1. Port marketing UX wins → app
2. 301 redirects + kill marketing review/auth/API proxy layer  
3. Fix CI status URL → point to app
4. Receipt page stays on marketing (public, unauthenticated)
