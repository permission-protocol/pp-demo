- Both Render services (web/worker) confirmed running same commit `f66fcad`

### 🚨 ROOT CAUSE IDENTIFIED
**`PP_VERIFY_API_KEY` resolves to SYSTEM TENANT, not permission-protocol company!**

The workflow uses `PP_VERIFY_API_KEY` for receipt verification, but this key belongs to a different tenant than where the receipt was created. The API correctly returns 404 because from that tenant's perspective, the receipt doesn't exist.

Meanwhile, the workflow's `PP_API_KEY` correctly resolves to `permission-protocol` company (where receipt lives).
