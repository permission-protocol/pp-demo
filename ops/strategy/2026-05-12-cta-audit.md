## Issues identified

1. **`/contact?audience=cco` doesn't resolve correctly.** `ContactPageClient.tsx` reads `?plan=` not `?audience=`. CCO traffic from the PR #340 section lands on the generic "Get in touch" form. **Critical fix.**
2. **No `cco` plan config exists** in `planConfigs` map.
3. **Inconsistent button text** for the same action: "See a blocked PR" vs "See blocked PR" vs "See the blocked PR", "Install on one repo" vs "Install GitHub App", "Read the GitHub quickstart" vs "Read the Quickstart".
4. **Inconsistent capitalization** of duplicate CTA slugs.
5. **No "Talk to a compliance engineer" handling on the contact page.** Even when query param is fixed, there's no copy that matches the CCO context.
6. **Receipt demo (`/r/demo`) reuses developer CTAs** ("Install GitHub App", "Book a 15-min founder call") even when visitor came from CCO surface.
7. **Pricing page CTA "Talk about agent-platform authorization"** sends enterprise visitors through a platform-partner narrative. Wrong audience.
8. **Site header has 4 CTAs in a row** (See receipt / Find gap / See blocked PR / Install). Too many parallel options for the user to choose from. Cognitive overload at the top of the funnel.

## Target state (after standardization)

### Two-track CTA system

Every page declares its **primary audience** (developer | cco | platform). CTA pairs derive from that.

| Audience | Primary CTA (low friction) | Secondary CTA (talk to a human) |
|---|---|---|
| developer | "See a blocked PR" → `app.permissionprotocol.com/demo/start?src={page}&audience=dev` | "Install on one repo" → `app.permissionprotocol.com/signup?next=github_app_install&src={page}` |
| cco | "See a signed receipt" → `/r/demo?audience=cco` | "Talk to a compliance engineer" → `/contact?plan=cco&src={page}` |
| platform | "View platform integration" → `/platforms/parallel-coding-agents` | "Talk about platform receipts" → `/contact?plan=platform&src={page}` |

### Routing standardization

- All `?audience=cco` → migrate to `?plan=cco`.
- Every `/contact?plan=X` link must have a matching config in `planConfigs`. Add `cco` plan config (see spec below).
- All demo links carry `?src={origin-page}&audience={dev|cco|platform}` for analytics segmentation.
- All install links carry `?src={origin-page}` for analytics segmentation.

### Header CTAs (currently 4, reduce to 2)

Keep the developer-track primary pair in the header for the SEO-driven traffic. The CCO surface gets its own CTA pair on the homepage section. Header simpler.

Desktop header (right side):
- Link: "Receipt" → `/r/demo`
- Link: "Docs" → `/docs`
- Link: "Incident tracker" → `/agent-incident-tracker`
- Primary button: "See a blocked PR" → demo
- Secondary button: "Install on one repo" → signup

(Removes "Find authorization gap" link from header; it stays accessible from the homepage CCO section and the incident tracker page itself.)

### Receipt page (`/r/demo`) CTAs

Currently shows three CTAs: Install / Book founder call / See blocked PR. Standardize to two with audience inference from query param:

- If `?audience=cco`: show "Talk to a compliance engineer" + "See a blocked PR"
- Else: show "Install on one repo" + "Book a 15-min founder call"

### Pricing page

- Current "Talk about agent-platform authorization" implies platform partner. Wrong default audience for pricing visitors.
- New default: "Talk to our enterprise team" → `/contact?plan=enterprise`
- Keep "Read the Quickstart" as secondary for the self-serve tier.

## Analytics requirement

Every standardized CTA must keep its existing `data-cta` and `data-track` attributes. Where a slug is being consolidated (e.g. "see-blocked-pr" duplicate variant unified to "try-blocked-pr-demo"), preserve the old slug in a hidden HTML comment so historical analytics still parse.
